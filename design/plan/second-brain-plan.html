Design draft · 27 Sep 2026

A second brain for everything you save

One place that pulls in your X bookmarks, YouTube playlists and saved videos, Instagram saves, screenshots and Feedly saves, has Claude sort and tag them, and lets you search, read, archive and retag each one on iPhone and the web. Nothing gets thrown away.

Stage: design, no code yetApps: iOS + webOwner: one person
How it works

Every item takes the same five steps

1. CollectA sync job, an import file, or the iPhone share sheet drops the raw item in.
2. Keep the raw copyStore the original data as is, before anything else touches it.
3. Fill inFetch the page text, images and author. Read the text inside screenshots.
4. Sort with ClaudeClaude picks a category, tags, a title and a two line summary.
5. ShowThe item lands in your inbox, ready to search, read, archive or retag.

The same item saved in two places (a link you bookmarked on X and also saved in Feedly) becomes one item that remembers both places and both dates.

Sources

What each source allows today

I checked each one against current docs. Only X and YouTube have a real, open way to read your saves. The rest need a workaround, and the plan below uses the most solid one for each.

X (Twitter) bookmarks

Official API
How
Sign in with X once (OAuth, bookmark.read scope), then a job pulls new bookmarks every few hours.
Cost
X now charges per read. Reading your own bookmarks counts as an "owned read" at $0.001 per post, so 1,000 bookmarks costs about $1. You need your own X developer app with billing on.
Catch
Developers report the API only returns your 800 most recent bookmarks. For older ones, a one time helper scrolls your bookmarks page in your own browser and saves what it sees. That helper is a gray area under X's terms, so we run it once, by hand, if you want the old ones.

YouTube playlists and saved videos

Official API, one gap
How
Sign in with Google once (read only YouTube access). A job then pulls your own playlists, every video in them, and your liked videos, and checks for new ones every few hours. It's free within YouTube's daily limit, which is far more than one person needs.
Catch
Since 2016 YouTube's API returns an empty list for Watch Later. So for Watch Later, and for playlists other people made that you saved, the plan is a Google Takeout export of your YouTube data, uploaded once. After that, new saves come in through the share sheet: tap Share on a video in the YouTube app and pick "Save to Brain".
Extra
For each video the app stores the title, channel, length and description, and pulls the captions where the owner allows it, so Claude can tag the video by what it says and search finds words spoken in it.

Instagram saves

No API
How
Past saves: request your data from Instagram (Accounts Center, Download your information, JSON). Its saved_posts.json file lists each post's link, the account, and when you saved it. You upload that file and the app imports it.
New saves: in Instagram, tap Share on a post and pick "Save to Brain". The iOS app catches it at once.
Catch
The export has no caption and no image, only links. To fill those in, the app can fetch the public post preview. Posts that got deleted stay as links with the account and date.

Screenshots (Google Photos)

Limited API
How
On iPhone: the iOS app asks for photo access and reads the Screenshots album on the phone itself. This is the best path, since your screenshots start there before they reach Google Photos.
Past screenshots in Google Photos: Google Takeout exports them as a zip you upload once. For odd ones, the web app opens Google's photo picker so you choose which to add.
Catch
Since March 2025 Google no longer lets outside apps read your whole Google Photos library. Apps only see photos you pick by hand. So no app can quietly sync all your Google Photos screenshots anymore.

Feedly saved for later

Paid plan only
How
Feedly's own API tokens are only for Enterprise plans now. The workable path: an IFTTT or Zapier rule "new article saved for later in Feedly" that sends each save to the app. For past saves, a one time export or a request to Feedly support for a personal token.
Catch
I still need to confirm the IFTTT or Zapier Feedly trigger works on your Feedly plan. If it does not, the fallback is the share sheet from the Feedly app, same as Instagram.

Anything else, by hand

Built in
How
Paste a link, type a note, or add a photo or file, from the web app or the iPhone share sheet. The share sheet also covers Safari, YouTube, Reddit and any app with a Share button.
Claude

How Claude sorts and tags

  • One call per item. Claude gets the item's text, the page it links to, and for images the picture itself (it can read text in screenshots). It also gets your current list of categories and tags, so it reuses them instead of inventing near copies.
  • It returns fixed fields: a title, a two line summary, one category, three to six tags, and the content type (thread, article, recipe, product, quote, place, video, and so on).
  • Your tags win. Tags Claude adds are marked "suggested". Tags you add or keep are marked "yours" and Claude never removes them. When you retag, the app saves the change as an example so Claude learns your style on later items.
  • Cheap first import. The big first import runs through Anthropic's batch mode, which costs half as much. A fast, small model (Haiku 4.5) does most items, and a stronger one (Sonnet 5) handles long articles or items the first pass is unsure about.
  • Your notes count. A note you add to a bookmark is searchable, and Claude reads it when tagging, so a note like "gift idea for Dad" can add a gifts tag.
  • Search by meaning. Each item also gets a vector, so "that thread about sleep and caffeine" finds it even if those words never appear.
{
  "title": "How to cut caffeine without losing focus",
  "summary": "Thread on tapering coffee over 2 weeks. Swaps and timing tips.",
  "category": "Health",
  "tags": ["sleep", "caffeine", "habits"],
  "kind": "thread"
}
Data

What we store

One Postgres database holds everything, with files (images, screenshots, saved pages) in object storage next to it. The original raw data from each source is always kept, so we can redo tagging later with a better model without fetching anything again. A full export (JSON plus files) is one button in Settings.

Order

Build order

Each step leaves you with something you can use.

  1. Core and add by hand

    Database, sign in, the web app with Inbox, Item and Add. You can save links and notes on day one.

  2. Claude sorting and search

    Tags, summaries, categories, word and meaning search, the side menu of tags and categories, notes, retag and archive.

  3. X bookmarks and YouTube

    Connect X and YouTube. Pull the latest 800 bookmarks, your playlists and liked videos, then sync every few hours. Sources screen goes live.

  4. iPhone app

    Same screens, plus the share sheet (covers new Instagram and Feedly saves) and the Screenshots album.

  5. Past Instagram, YouTube Watch Later, Feedly and Google Photos

    Import the Instagram JSON, the Google Takeout zips (YouTube and Photos), and set up the Feedly rule.

  6. Later

    Ask questions across your whole archive, weekly "things you saved and forgot" digest, and the one time X backfill if you want it.
