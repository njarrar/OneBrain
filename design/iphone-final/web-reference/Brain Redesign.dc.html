1b Audit of the current web app

Why the app feels early, and what changes

Based on web/src in this repo and your screenshots. The prototype in 1a applies every change below.

Every filter reloads the page Language, media, layout and category are all links, so each click is a server round trip and a full redraw. This is most of the "not snappy" feeling. Change: filter on the client with the URL kept in sync, instant results, and keyboard triage (J, K, E, U, /).
Too many controls before any content Search, Add, nine pill buttons and a switch sit in two rows, all at the same weight. The page asks for decisions before showing anything. Change: one search field and one Filter menu. Active filters appear as removable tokens.
Cards repeat themselves A card can hold 12 parts. The summary box often restates the text, and the category shows three times: top edge, dot and pill. Change: author line, two lines of text, one line of summary, one category label.
Masonry scrambles the order CSS columns fill top to bottom, so newest-first reads down column one, then column two. Cards shift as pictures load. Change: a dated list with a fixed thumbnail slot. Nothing moves.
Opening an item loses your place The item page replaces the list, so triaging 128 saves is 128 trips back. Change: a reading pane beside the list. Opening marks it read; archiving moves to the next one.
Edits feel like forms Category is a select plus a Set button, the note needs Save note, and tags need Add. Change: category popover, inline tags (click a dashed one to accept it), note that saves itself, undo instead of confirm.
Every button is amber Open original, Archive, Mark read, Set, Add and Save note are all filled or outlined amber, so nothing leads. Change: quiet toolbar buttons with shortcut hints. The accent marks only selection, unread and Add.
Type is cramped Plus Jakarta Sans with negative tracking at 14.5px closes up word spaces in the screenshots ("Searchbyword"). Mono uppercase labels head every panel and menu group. Change: Figtree at normal tracking, mono only for handles, dates and counts, sentence-case labels.
Two designs, double the upkeep Vault and Sunroom each carry their own radii, shadows and chip formulas, and globals.css repeats each palette for system mode. Change: one design with light and dark from a single token set. CSS light-dark() removes the repeated blocks.
Suggested order: client-side filtering and the reading pane first (how it feels), then cards, buttons and type (how it looks), then merging the themes.
